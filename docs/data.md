# Данные OpenDota и тепловая карта

[← Главная](../README.md) · [Использование](usage.md)

## От профиля до карты

1. Ввод преобразуется в `account_id` OpenDota.
2. Приложение запрашивает профиль игрока и агрегированную карту вардов.
3. Поля `obs` и `sen` превращаются в таблицу координат и количества.
4. Координаты переводятся в пространство локальной карты.
5. Plotly отображает точки или сглаженную плотность.

## Идентификация игрока

Для SteamID64 используется преобразование:

```text
account_id = SteamID64 - 76561197960265728
```

Для custom URL `/id/…` приложение читает `steamID64` из XML этого профиля. Если XML недоступен, проверяет данные этого же профиля в HTML. Поиск по отображаемому нику не используется: он может совпадать у нескольких людей.

Приложение не требует входа в Steam или собственного Steam API key. Если Steam не возвращает ID, можно ввести числовой ID вручную.

## Запросы

| Задача | Метод и путь |
| --- | --- |
| Профиль игрока | `GET /players/{account_id}` |
| Агрегированные варды | `GET /players/{account_id}/wardmap?limit=N&significant=0` |
| Запрос обновления истории | `POST /players/{account_id}/refresh` |

Базовый адрес: `https://api.opendota.com/api`.

`N` — выбранный лимит 1–1000. Приложение передаёт `significant=0`, включает обычные и нестандартные матчи и не предоставляет отдельного фильтра их типов.

Ответы GET кешируются на 120 секунд. Успешное определение custom Steam URL кешируется на 300 секунд. Обновление истории очищает кеш API; само обновление OpenDota выполняется асинхронно.

## Формат таблицы

Обычный ответ wardmap содержит вложенную структуру координат:

```json
{
  "obs": {"100": {"120": 3}},
  "sen": {"105": {"125": 2}}
}
```

Это **учебный пример**, не статистика реального игрока.

| type | x | y | count |
| --- | --- | --- | --- |
| Observer | 100 | 120 | 3 |
| Sentry | 105 | 125 | 2 |

Две строки здесь соответствуют пяти установкам. Показатели и итог складывают `count`. CSV сохраняет эту агрегированную таблицу, оба типа и исходные координаты OpenDota.

В ответе не используются ID матчей и время каждой установки. По агрегированной таблице приложение не вычисляет, сколько именно матчей имеют полные данные.

## Координаты и подложка

Для сетки OpenDota используются границы 64–191. Размер изображения — 1024×1024:

```text
image_x = (x - 64) / 127 * 1024
image_y = (191 - y) / 127 * 1024
```

У изображения Y направлен вниз; при рисовании Plotly направление преобразуется. Источник формулы и происхождение подложки описаны в [assets/README.md](../assets/README.md).

Карта загружается локально из `assets/map_7_39.png` и проверяется как изображение. Обращение к внешнему сайту за фоном не требуется. Подложка соответствует 7.39, а не автоматически выбранному патчу матча. Точная привязка всех объектов по реальным реплеям не проверена.

## Как считается тепловой слой

На сетке 128×128 к каждой позиции добавляется гауссово пятно с весом `count`. Стандартное отклонение фиксировано: 22 единицы изображения 1024×1024.

```text
density(X,Y) = sum(count_i * exp(-distance_i² / (2 * 22²)))
normalized = (density / max(density)) ^ 0.72
```

Рассчитывается только выбранный тип: Observer **или** Sentry. Низкая плотность отображается прозрачным цветом, высокая — более ярким. Маркеры поверх слоя при включении содержат оба типа.

Нормализация производится отдельно для каждого результата. Тепловой слой пригоден для изучения распределения внутри одного набора; для сравнения количества между наборами используй показатели и CSV. Он не отображает обзор, успешность, длительность жизни или качество варда.

## Почему статистика неполная

Приложение может показать только доступные координаты OpenDota. Если реплей не разобран, его варды могут отсутствовать. Наличие матча в истории не гарантирует наличие координат.

Поэтому результат «5 вардов, лимит 10 матчей» не означает, что всего за десять матчей было пять установок. Предупреждение в интерфейсе напоминает об ограничении, но не измеряет точное покрытие.

Большой лимит может добавить доступные позиции. Обновление истории может помочь получить новые данные, но не гарантирует полноту или разбор всех реплеев.

## Сетевые обращения

Приложение обращается к OpenDota за статистикой, а при custom URL — к Steam Community для определения ID. Лаунчер EXE запускает сервер на `127.0.0.1:8501` и отключает сбор статистики использования Streamlit.

Экспорт запускается пользователем и скачивается через браузер. Не помещай пароли, API-ключи или приватные сведения в issues и снимки экрана.

Документация описывает реализацию текущего приложения. Сведения об API и доступности данных: [OpenDota](https://www.opendota.com/), [документация API](https://docs.opendota.com/).
