## Основные функции app.py

| Функция | Вход → результат |
| --- | --- |
| extract_account_id | URL или число → account ID, если возможно прямое извлечение |
| resolve_steam_vanity | custom URL → ID через XML/HTML того же профиля |
| resolve_profile | пользовательский ввод → account ID |
| api_get / api_post | путь API → JSON или сообщение об ошибке |
| normalize_wardmap | obs/sen → DataFrame type,x,y,count |
| world_to_image | координаты сетки → координаты изображения |
| density_trace | позиции выбранного типа → Plotly Heatmap |
| build_map | данные и настройки → Plotly Figure |
| png_bytes | Figure → PNG, либо None при недоступном экспорте |
| desktop_exit_enabled | frozen + PID лаунчера → доступна ли остановка EXE |
| schedule_desktop_exit | завершение именно desktop-процесса после обновления UI |

## Состояние и обновление

После загрузки в session_state сохраняются account_id, player, df, source_profile и loaded_limit. Изменение слоёв перерисовывает загруженные данные. Изменение лимита требует повторной загрузки, чтобы интерфейс не выдавал старый набор за новый запрос.

Счётчики складывают count во всём наборе. Фильтрация типов происходит при построении фигуры. CSV берётся из исходного df, поэтому не зависит от скрытых маркеров.

Кеш GET имеет TTL 120 секунд, кеш разрешения vanity URL — 300 секунд. Запрос обновления истории очищает кеш API. Эти интервалы описывают локальный кеш, а не срок обновления данных OpenDota.

## Границы демонстрации

demo_app.py не меняет app.py. Он использует patch для requests.get/post на время выполнения приложения и возвращает только фиксированные ответы. Учебный набор не зависит от лимита. Демо запускается отдельной командой и не добавляется в обычный EXE.

Автономный HTML использует фигуры, построенные существующим build_map на том же наборе. Его управляющая панель — отдельная презентационная оболочка. Это не второй клиент к OpenDota и не полная копия Streamlit.

## Что учитывать при изменениях

При изменении формата данных проверяй сумма count, пустые obs/sen и сохранение координат. При изменении плотности — раздельные типы, нормализацию и прозрачный низкий уровень. При изменении лаунчера — завершение процесса, порт 8501 и работу обычного Python-запуска.

README должен описывать доступные возможности, а не планы. Новая функция требует обновления соответствующего руководства и, если её демонстрируют, учебного сценария.
