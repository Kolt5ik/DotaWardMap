# Как участвовать в DotaWardMap

[← Главная](README.md) · [English overview](README.en.md#contributing)

Приветствуются исправления, улучшения документации, переводы и отчёты об ошибках. Для большого изменения сначала открой issue: это поможет согласовать задачу до написания кода.

## Ошибки и идеи

Используй [шаблоны issues](https://github.com/Kolt5ik/DotaWardMap/issues/new/choose). Перед созданием проверь, нет ли уже похожего отчёта.

Для ошибки нужны версия приложения, ОС, способ запуска, шаги и точный текст сообщения. Не публикуй пароли, токены и приватные данные.

## Ветка и pull request

Если есть доступ к репозиторию, работай в отдельной ветке. Если доступа нет, сделай fork и создай ветку в нём.

В клонированном репозитории с настроенным `origin`:

```powershell
git switch main
git pull --ff-only origin main
git switch -c feature/describe-your-change
```

Установи зависимости по [инструкции](docs/installation.md). После изменения:

```powershell
git diff --check
git status --short
```

Добавляй конкретные изменённые файлы, чтобы случайно не закоммитить окружение или выгрузки. Пример для правки README:

```powershell
git add README.md
git commit -m "docs: clarify the quick start"
git push -u origin feature/describe-your-change
```

Открой pull request в `Kolt5ik/DotaWardMap` с целевой веткой **main**. Для fork выбери свою ветку из fork как источник.

## Что проверить

| Изменение | Проверка |
| --- | --- |
| Документация | Ссылки, оглавление, команды, отображение README на GitHub |
| Интерфейс | Запуск, загрузка профиля, переключатели, скриншоты до/после |
| Данные | Вложенный формат obs/sen, сумма count, пустой ответ, координаты |
| Тепловая карта | Выбор типа, прозрачный фон, точки поверх, отключение слоя |
| Лаунчер или упаковка | Windows EXE, открытие браузера, остановка процесса и освобождение порта |
| Экспорт | CSV для обоих типов; результат или корректное сообщение при недоступном PNG |

В репозитории пока нет автоматизированного набора тестов. Описывай реально выполненные проверки; для новой логики добавляй тесты, когда они защищают значимое поведение.

Базовая проверка синтаксиса на Windows:

```powershell
.\.venv\Scripts\python.exe -m py_compile app.py launcher.py
```

На Linux/macOS используй `.venv/bin/python` вместо пути Windows. Для проверки упакованного приложения запусти workflow на своей ветке по [инструкции сборки](docs/installation.md#github-actions-тестовая-сборка).

## Описание PR

Объясни проблему, итоговое поведение и проверки. Для UI приложи изображение; для изменения данных — короткий пример до/после. Укажи ограничения, если проверка не выполнена.

Слияние выполняется после ревью. Для документации обычно не требуется новый EXE-релиз. Процесс релиза описан в [инструкции](docs/installation.md#публикация-релиза).

## Ориентиры проекта

Сохраняй агрегированный анализ последних N матчей, возможность отключить тепловой слой и раздельную плотность Observer/Sentry. Не выдавай данные OpenDota за полную статистику всех запрошенных матчей. Изменение этих принципов сначала обсуди в issue.

## Уважительное общение

Обсуждай конкретные решения и ошибки. Без оскорблений, дискриминации и публикации личных данных. Помогай новичкам воспроизвести проблему.
